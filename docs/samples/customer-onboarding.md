# 신규 고객 온보딩 점검 보고서

외부 협력사 제출용 문서입니다. 아래 표와 본문은 거버넌스 표준화 전 원본입니다.

## 1. 대상 고객

| 회원번호        | 주민번호       | 나이 | 회원등급 | 계약 ID     |
| --------------- | -------------- | ---- | -------- | ----------- |
| CUST-0000000001 | 900101-1234567 | 34   | VIP      | CT-2026-001 |
| CUST-0000000002 | 0205154123456  | 23   | GOLD     | CT-2026-002 |
| CUST-0000000003 | 851120-******* | 40   | SILVER   | CT-2026-003 |

## 2. 점검 내용

- 고객 식별번호는 CUST- 접두사와 숫자 10자리로 구성한다.
- 주민 등록 번호는 외부 문서에 그대로 노출하지 않는다.
- RRN은 본인 확인 단계에서만 사용하고, 확인이 끝나면 RRN을 폐기한다.
- 만 나이가 19세 미만이면 VIP 등급을 부여하지 않는다.
- Customer Grade와 Contract No는 매월 대사한다.
- 고객 ID가 없는 계약은 등록하지 않는다.

## 3. 단어 경계 확인

나이스평가정보 조회 결과와 RRNX 내부 코드는 표준 용어가 아니므로 바꾸지 않는다.

## 4. 시스템 연계

연계 API는 [주민번호 조회 가이드](https://example.com/docs/주민번호)를 따른다. 필드명은 `주민번호`, `회원번호`를 그대로 사용한다.

```json
{
  "회원번호": "CUST-0000000001",
  "주민번호": "900101-1234567"
}
```
