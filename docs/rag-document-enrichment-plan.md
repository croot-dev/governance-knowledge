# RAG 문서 보강 서비스 작업 계획안

작성일: 2026-10-10 · 상태: 구현 전 제안

목표는 기존 Governance Knowledge를 재사용해 멀티모달 파일을 개별·폴더·압축 형태로 받고, 파일별 content를 의미분석하여 근거가 있는 메타데이터·보강안·규칙 적용 결과를 생성하는 서비스다. 상세 책임·데이터·실행 흐름은 [아키텍처 구성안](rag-document-enrichment-architecture.md)을 기준으로 한다.

## 1. 범위와 기본 결정

첫 버전은 이미지(PNG/JPEG/WebP), PDF(텍스트·스캔·혼합), MD, TXT, LOG를 입력으로 받는다. 단일·다중 파일, 하위 경로를 보존한 폴더, ZIP 업로드를 지원한다. TXT·LOG는 UTF-8을 기본으로 하며 그 외 인코딩은 검증된 adapter가 없으면 명시적으로 실패 처리한다. 암호화·중첩 ZIP과 기타 압축 형식은 미지원으로 표시한다.

전체 흐름은 `업로드·배치 목록 확정 → 파일별 추출(OCR/vision 포함) → 공통 content 구성 → RAG 의미분석 → 거버넌스 적용 → content 보강 → 검증·검토 → 결과 묶음`이다. 문서 유형·주요 개념 추출, 용어 표준화, 근거 설명 보강, 값 단위 규칙 검사와 파일별 결과 다운로드를 제공한다. PDF·이미지는 보강된 content JSON과 Markdown을 출력하며 원본 바이너리 마스킹은 별도 후속 기능이다.

패키지 관리자는 pnpm, 구현 언어는 기존 프로젝트에 맞춘 TypeScript, UI는 shadcn/ui를 유지한다. LangChain으로 검색·모델 호출을 구성하고, LangGraph는 검토 재개·실패 복구를 제공하는 MVP 단계에 사용한다. 초기에는 에이전트가 임의 도구를 선택하는 구조 대신 단계가 정해진 RAG 파이프라인을 구현한다.

직원별 현재 부서·직급 연동, 실제 조회 권한 enforcement, Graph DB, 전사 커넥터, 자동 정책 생성·활성화는 후속 범위다. 회사 직급과 문서 유형의 **정의**는 이번 거버넌스 확장 범위에 포함한다.

## 2. 작업 단계와 통과 기준

| 단계                  | 주요 작업과 산출물                                                             | 선행 조건 | 완료 기준                                                    |
| --------------------- | ------------------------------------------------------------------------------ | --------- | ------------------------------------------------------------ |
| 0. 계약·평가 기준     | 보강 종류, 공통 content·배치 계약, 참조 문서, 모델·전송 정책, 형식별 평가셋    | 없음      | 혼합 폴더·ZIP의 입력·출력 예시와 평가 기준 확정              |
| 1. 거버넌스 조회 계약 | 문서 유형·직급 기준정보, 규칙 범위·버전 snapshot, 정확 규칙 조회               | 0         | 코드로 정의 조회 가능, 과거 Rule 내용 재현 가능              |
| 2. 업로드·추출·저장   | 폴더·ZIP manifest, 형식별 parser·OCR·vision, 공통 content, 불변 원본·출처 저장 | 0         | 모든 지원 형식의 위치 추적, 목록 완결성·실패 표시 검증       |
| 3. LangChain RAG PoC  | 실제 embedding, governance/reference retriever, 구조화 분석, 보강 초안         | 1, 2      | 형식별 실제 샘플에서 근거 있는 분석·보강 제안, UNKNOWN 처리  |
| 4. 규칙·변경 검증     | scope 확인, 값 구간 규칙 평가, patch 적용·충돌·출처 검사                       | 3         | 잘못된 의미의 값이 자동 수정되지 않음, 미확정 규칙 누락 방지 |
| 5. 비동기·LangGraph   | 배치 조정·파일별 큐, checkpointer, 재시도, interrupt·resume, 결과 저장         | 4         | 부분 실패·중단 복구, 실패 파일 재처리, 결과 중복 반영 방지   |
| 6. 검토 UI·운영       | 폴더·ZIP 업로드, 파일별 상태·근거·diff·검토, 결과 묶음, 권한·계측              | 5         | 목록·부분 결과 확인, 승인한 변경만 반영, 버전 변경 감지      |

순서는 `0 → (1, 2) → 3 → 4 → 5 → 6`이다. 1·2의 독립 작업은 병행 가능하다. 3단계 PoC 평가 후 품질이 확보되지 않으면 자동 적용 범위를 늘리지 않고 검색·분류 기준을 보완한다. 검토 UI 와이어프레임과 API 계약 검토는 앞 단계부터 진행할 수 있다.

기간은 투입 인원과 모델 응답시간, 기준정보 준비 상태가 정해진 뒤 산정한다. 위 표는 구현 의존성과 단계별 완료 조건이며 확정 일정이 아니다.

## 3. 단계별 구현 항목

### 0. 계약 및 평가셋

- 보강 옵션을 `ANNOTATE`, `STANDARDIZE`, `MASK`, `ADD_GROUNDED_NOTE`로 정의한다. 옵션별 자동 변환·검토 정책을 고정한다.
- 모델 출력에서 `INFERRED`, `CONFIRMED`, `UNKNOWN`을 구별하고 원문 근거와 외부 근거를 별도 표현한다.
- 30~50개 정도의 합성·비식별 문서로 시작하되 모든 지원 형식과 혼합 폴더·ZIP을 포함한다. 개발용과 보류 평가용 문서를 구분한다.
- 스캔·혼합 PDF, 문자 없는 도표 이미지, 흐린 OCR, 손상 파일, 같은 이름의 다른 경로, 미지원 파일이 섞인 배치를 포함한다.
- 동음이의어, 같은 숫자 형식의 다른 엔티티, 문서 유형 혼합·누락, 상충하는 사내 지침, 긴 표·코드, 근거 없는 요청을 포함한다.
- 생성 LLM과 실제 Qwen embedding을 별도로 연결해 품질·토큰·시간을 측정한다. mock 모드 결과는 의미 품질 평가에서 제외한다.

### 1. Governance 컴포넌트 계약

- `DocumentType`: code, 정의, 긍정·부정 분류 예시, version, 상태.
- `JobGrade`: code, 명칭, gradeSchemeId, 비교 순서, version, 상태. 기존 Term과는 참조 관계로 연결한다.
- `GovernanceCatalog` 포트: 기준정보 조회, Term 후보의 전체 정의, 해당 Term·문서 유형·범위에 적용할 규칙 조회.
- 현 `ActiveRule`에 없는 termId, scope, version, priority를 포함한 별도 snapshot DTO를 정의한다.
- 현재 Rule이 Term 하나에 연결되는 제약은 유지한다. 문서 수준의 필수 규칙·문서 유형별 적용은 별도 scope binding으로 정의하고 기존 데이터와의 호환 방법을 명시한다.
- 확정된 규칙에 의미 검색 topK 누락이 발생하지 않도록 구조화 조회 경로를 만든다.

### 2. 문서·참조 지식 처리

- 업로드 배치·item·manifest를 만들고 폴더 상대 경로를 보존한다. ZIP 해제는 경로 이동·링크·중복 경로를 차단하고 용량·개수·깊이·확장 비율을 제한한다. 목록 미확정을 정상 완료로 표시하지 않는다.
- MD AST, TXT, LOG, PDF, 이미지용 `ContentExtractor` adapter를 구현한다. PDF는 페이지별 텍스트·이미지·OCR를 조합하고 이미지·도표는 vision 분석을 지원한다. OCR 추출과 의미 추론을 구분한다.
- 공통 `ContentDocument`에 원본·추출 버전, block, 표·이미지 참조, 페이지·영역·행 위치, 엔진 버전, 추출 품질·실패 사유를 저장한다. 로그의 시간대나 누락 필드를 임의로 채우지 않는다.
- `src/domain/transform.ts`의 현재 구간 분리와 전역 패턴 적용을 확인하고, 신규 경로에 AST 기반 위치 모델을 추가한다.
- 표 열 헤더·셀, 키:값, 문장 내 언급을 block/span에 연결한다. 값의 의미가 불확실하면 자동 치환 후보에서 제외하고 보고한다.
- 원본 불변 version, content hash, 파일 저장 adapter, 분석 산출물 저장 구조를 추가한다.
- `ArtifactStore`에 로컬·S3 adapter를 구현한다. 로컬 PoC는 영속 볼륨, 서비스 MVP는 SeaweedFS를 기본안으로 사용한다. 원본·추출 이미지·보강본은 객체 저장소에, 버전·상태·object 참조는 PostgreSQL에 보관한다.
- stream 업로드, 서버 생성 key, 크기·SHA-256 검증, 업로드 완료 후 DB 참조 확정·추출 큐 등록을 구현한다. DB와 저장소 간 부분 실패를 재시도로 복구하고 미완료 업로드·고아 객체를 정리한다.
- 승인된 참조 문서에 source version·chunk ID·읽기 범위를 부여하고 별도 LanceDB 테이블에 적재한다.
- 기존 governance index-worker에 참조 인덱싱 책임을 명시적으로 추가하되 분석 작업 큐와 섞지 않는다.

### 3. LangChain RAG PoC

- 기존 검색 API를 그대로 모델 컨텍스트로 넣지 않고, 정의·출처·version을 제공하는 retriever adapter를 만든다.
- 입력 문서의 제목·절·표·OCR·이미지 설명·로그 이벤트로 기준정보와 참조 문서를 검색한다. 필요한 시각 자료는 vision 모델에 전달하며 LLM에 허용된 근거만 제공한다.
- 문서 유형·엔티티와 값 연결을 구조화 출력으로 추출한다. 원문에 없는 인용과 존재하지 않는 code는 검증 오류로 처리한다.
- 첫 분석 결과로 정확한 규칙을 조회한 뒤, 필요한 경우 두 번째 모델 호출로 설명 보강안을 생성한다.
- 근거 부족·분류 충돌·검색 장애를 정상 보강 완료와 구분한다.
- 호출 전 모델별 TokenBudgeter로 지침·schema·검색 근거·문서·이미지와 출력 예약량을 계산한다. embedding 입력 한도도 별도로 검사한다. 초과 시 근거 정리·구조 기반 재분할 후 재계산하며 필수 규칙을 누락시키지 않는다.
- 긴 표·로그·PDF를 위치가 있는 chunk로 분할하고 계층 병합에도 같은 예산을 적용한다. 문서 전체 검사에서 원문 재조회와 UNKNOWN 처리를 지원한다.
- 승인된 직급 비교 정의가 있을 때 “과장 이상”의 의미를 해석하되, 문서 작성자·조회자의 직급을 추정하지 않는다.

### 4. 규칙 평가와 보강 검증

- MASKING은 `pattern → replacement → resultPattern` 계약과 코드 검증을 재사용한다.
- FORMAT / ENUM / RANGE는 엔티티에 연결된 값에 적용한다. REQUIRED는 필요한 항목의 범위가 정의됐을 때만 평가한다.
- 의미로 판정하는 정책은 LLM 판정 근거와 불확실성을 별도로 기록한다. 결정적 코드 검사와 같은 확정 수준으로 표현하지 않는다.
- 겹치는 patch, 오래된 beforeHash, 코드·링크 변경, 존재하지 않는 출처, 보강 과정의 새 위반을 검사한다.
- 모든 필수 규칙이 `평가됨 / 적용 대상 아님 / 판단 불가` 중 하나로 설명되도록 적용 목록을 기록한다.

### 5. LangGraph와 비동기 실행

- 배치 조정자가 파일별 추출·분석 run을 등록하고 제한된 동시성으로 실행한다. 한 파일의 실패가 다른 결과를 취소하지 않으며 실패 파일만 재시도한다.
- 배치에는 목록 확정 여부와 완료·실패·미지원·검토 대기 개수를 표시한다. 파일·페이지·배치별 시간·호출·용량 한도를 적용한다.
- 실행할 단계 함수를 그래프 node로 연결한다. PoC의 도메인·adapter 코드를 다시 작성하지 않는다.
- analysis_jobs에는 lease·heartbeat·실행 소유자를 저장하고, 동일 run 동시 실행을 제한한다.
- PostgreSQL checkpointer와 `thread_id = runId`를 사용한다. 큐 재시도 시 checkpoint로 재개한다.
- 검토 대기에서 worker 자원을 해제하고, 검토 이벤트에 의해 명시적으로 재개한다.
- idempotency key, artifact unique 제약, 결과 저장 transaction으로 중복 확정을 방지한다.
- 모델 timeout·검색 장애·스키마 오류·근거 부족 각각의 재시도와 검토 전환 기준을 구현한다.
- provider 종료 사유·출력 잘림·stream 단절을 정규화한다. 정상 종료여도 schema·근거·요청 block coverage가 충족되지 않으면 성공으로 확정하지 않는다. 잘린 JSON을 임의 복구하거나 단순 이어쓰기로 확정하지 않는다.
- stage·chunk별 검증 결과를 영속 저장하고 미확정 단위만 재실행한다. 재분할 부모·자식 관계와 문서 coverage를 추적하고 전체 완료는 서버가 판정한다.
- 입력 초과는 재분할, 출력 초과는 출력 예산 조정 또는 작업 축소, 일시 장애는 제한 재시도로 처리한다. rate limit에는 backoff·동시성·토큰 처리량 제어를 적용한다.
- 파일·배치 예산을 호출 전에 원자적으로 예약하고 실제 usage로 정산한다. 재시도·재개도 누적 한도를 공유하며 예산 소진은 `BUDGET_EXHAUSTED`로 기록한다. 분할 깊이·최소 단위·총 호출 수도 제한한다.

### 6. 검토 UI와 운영

- 파일·폴더·ZIP 업로드와 상대 경로별 상태를 제공한다. 공통 content의 전후 diff, PDF 페이지·이미지 근거 영역, 추출한 유형·Term, 규칙 적용 결과를 표시한다.
- 파일별 검토·재시도와 결과 묶음 다운로드를 제공한다. manifest에 성공·실패·미지원 파일을 모두 기록하고 기본 보강본 묶음에는 원본 바이너리를 포함하지 않는다.
- 변경별 수락·거절과 분류 수정, 최종 export를 제공한다. 검토 이후 원본·정책 버전이 달라지면 재분석을 요청한다.
- 기존 인증 없는 로컬 MVP를 실제 회사 문서 서비스로 운영하기 전에 로그인·검토자 권한·참조 문서 읽기 권한을 연결한다.
- 원문·분석 산출물·checkpoint·추적 로그의 보존·삭제 정책을 일관되게 적용한다.
- SeaweedFS용 Compose 프로필과 로컬 저장 프로필을 제공한다. S3 인증·비공개 접근·영속 볼륨을 설정하고 filer 메타데이터·객체·PostgreSQL 참조의 백업 및 복구를 검증한다. 저장소만 추가하기 위해 LanceDB의 로컬 저장 방식을 변경하지 않는다.
- run별 모델·프롬프트·프로필 버전, 토큰·비용, 처리 시간, 검색 근거 수, 검증 실패·검토 전환 사유를 기록한다.
- 처리 chunk/전체 chunk, 페이지, 현재 단계, 중단 사유와 재개 가능 여부를 표시한다. 부분 산출물을 최종 완료 결과와 구분한다.
- LangSmith 등 외부 관측 도구는 선택 사항으로 두고 원문 전송 정책을 충족할 때만 연결한다.

## 4. 예상 코드 배치

초기에는 현재 저장소에 기능 단위로 추가한다. 컴포넌트 독립성은 포트로 확보하고 전체 저장소를 먼저 monorepo로 재작성하지 않는다.

```text
src/domain/enrichment/              분석·근거·patch·결과 계약
src/application/enrichment/         분석, 보강, 검토 유스케이스
src/application/ingestion/          배치·폴더·ZIP 입력, manifest, 파일별 작업 등록
src/infrastructure/extractors/      MD·TXT·LOG·PDF·이미지 추출, OCR·vision adapter
src/infrastructure/langchain/       모델 및 retriever adapter
src/application/enrichment/budget/  입력·출력 예약, coverage, 재분할·누적 예산 정책
src/infrastructure/langgraph/       workflow, state, checkpoint 연결
src/infrastructure/knowledge/       승인된 참조 문서·chunk·검색
src/infrastructure/artifacts/       원본·파생 파일의 Local/S3 adapter (SeaweedFS)
src/app/api/documents/              원본 버전 등록
src/app/api/upload-batches/         배치 업로드·완료·상태·결과 묶음 API
src/app/api/analysis-runs/          작업·검토·결과 API
src/components/enrichment/          결과·diff·근거·검토 UI
scripts/analysis-worker.ts         신규 분석 작업 worker
migrations/                        신규 version·run·기준정보 테이블
evals/document-enrichment/          보류 정답셋 및 모델 품질 평가
```

도입 후보는 `@langchain/core`, 선택 모델 provider adapter, `@langchain/langgraph`, PostgreSQL checkpointer package, AST parser다. 실제 설치 시 현재 Node·Zod 버전과의 호환성을 확인하고 pnpm lockfile로 고정한다. 단순 모델 호출에 agent API를 필수로 사용하지 않는다.

## 5. 검증 및 수용 기준

기존 핵심 테스트와 문서 변환 회귀 검증을 유지한다. 추가 자동 테스트는 계약·원본 보존·복구에 집중하며 CRUD별 반복 테스트나 UI snapshot suite를 만들지 않는다. 모델 품질은 unit test 통과와 분리해 실모델 평가셋에서 측정한다.

| 검증 영역     | 수용 기준                                                                               |
| ------------- | --------------------------------------------------------------------------------------- |
| 원본 보존     | 원본 hash 불변, 수락한 patch 외 구간 변경 없음                                          |
| 객체 저장     | 로컬·SeaweedFS 읽기/쓰기/삭제 계약, 업로드 중단·DB 확정 실패 복구, 권한·보존·복원 검증  |
| 멀티모달 추출 | 지원 형식별 추출 정확성·누락 측정, 페이지·영역·행 근거 추적, OCR 불확실성 표시          |
| 배치 입력     | 상대 경로 보존, 압축 경로·확장 한도 검사, 미지원·손상 파일과 목록 미확정 명시           |
| 부분 처리     | 일부 실패 시 다른 파일 결과 유지, 실패 파일만 재시도, 결과 manifest에 모든 항목 포함    |
| 출처          | 모든 외부 사실 보강에 유효한 source version·근거 위치 존재                              |
| 의미 연결     | Term별 precision/recall과 문서 유형별 혼동행렬을 제출; 자동 적용 기준은 보류셋으로 결정 |
| 검색          | 기준정보·정확 규칙 조회 누락과 Vector 검색 누락을 별도로 계측                           |
| 패턴 오탐     | 같은 형식의 주문번호를 개인정보로 확정하지 않는 사례 검증                               |
| 보강 정확성   | 없는 사실을 생성하지 않고 근거 부족을 UNKNOWN/검토로 반환                               |
| 규칙 적용     | 필수 규칙 누락·적용 미확정을 성공으로 숨기지 않음                                       |
| 원문 구조     | 긴 표·코드·링크·인용문의 허용되지 않은 변경 없음                                        |
| 복구          | 모델 호출·결과 저장 중 프로세스 종료 후 중복 결과 없이 재개                             |
| 검토          | 승인 전 원본·정책 변경 시 오래된 결과 확정 차단                                         |
| 비용·지연     | 문서 길이별 호출 수·토큰·p50/p95 측정 후 운영 한도 결정                                 |
| 토큰 경계     | 한글·긴 표·로그·이미지에서 입력/출력 한도 경계 검사, 병합 호출도 예산 준수              |
| 응답 중단     | 출력 잘림·stream 단절·정상 종료 후 누락을 주입해 불완전 결과의 성공 확정을 차단         |
| 이어서 처리   | chunk 저장 후 worker 종료·재분할·재개 시 완료 결과 재사용, coverage 누락·중복 적용 없음 |
| 예산 제한     | 동시 호출·rate limit·반복 실패에서도 누적 한도와 최대 재시도 준수, 중단 사유 표시       |

“LLM confidence 0.9 이상이면 자동 승인” 같은 고정 기준은 사용하지 않는다. 구조화 출력 성공 여부나 검색 유사도만으로 자동 적용을 허용하지 않는다.

## 6. 구현 착수 시 확정할 사항

아래는 계획 수립을 막는 질문이 아니라, 실제 모델 연결·문서 저장 전에 확정할 배포 설정이다.

| 항목        | 계획의 기본안                                      | 확정 시점                    |
| ----------- | -------------------------------------------------- | ---------------------------- |
| 보강 범위   | 요약·표준 용어·마스킹·근거 설명 제안               | 단계 0                       |
| 입력 형식   | 이미지·PDF·MD·TXT·LOG, 폴더·ZIP; 형식별 한도 설정  | 단계 0~2                     |
| 추출 모델   | OCR와 vision adapter 선택, 페이지·영역 근거 보존   | 단계 0~3                     |
| 결과 형식   | 파일별 content JSON·보강 MD, 배치 manifest·묶음    | 단계 0                       |
| 원문 저장   | 불변 버전 저장, 저장·전송 범위 설정                | 단계 0, 실제 문서 적재 전    |
| 파일 저장소 | 로컬 PoC는 볼륨, 서비스 MVP는 SeaweedFS S3 adapter | 단계 2, 버전·API 호환성 확인 |
| 생성 LLM    | provider 교체 가능, 사내 또는 허용된 외부 모델     | 단계 0~3                     |
| 참조 지식   | 승인된 회사 자료만, 대상 문서 자동 편입 없음       | 단계 0~2                     |
| 적용 정책   | 메타데이터 저장 + 내용 변경 검토 후 확정           | 단계 0                       |
| 인증        | 로컬 PoC 후 실제 사용자 검토 운영 전 연결          | 단계 6 이전                  |
| LangGraph   | PoC 이후 중단 복구·검토 재개 MVP부터 도입          | 단계 5                       |

기존 [의미 매칭 로드맵](semantic-matching-roadmap.md)의 AST·평가셋은 단계 0~2, 실제 embedding·LLM 판정은 단계 3, 추천·피드백·권한은 단계 6에 연결한다. 여기서 embedding은 의미 후보 검색을 위한 선택된 구현 방식이며, 모든 규칙 적용의 필수 전제는 아니다.

## 7. 구현 현황 (2026-10-10)

모델·OCR 선택이 필요 없는 범위를 먼저 구현했다. OCR은 `qwen3-vl:2b-instruct-q4_K_M`, embedding은 `Qwen3-Embedding-0.6B-GGUF`(1024차원)로 확정해 Docker Compose 서비스로 실행한다. 3단계는 생성 LLM 확정 후 진행한다.
